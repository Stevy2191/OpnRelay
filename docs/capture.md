# Capture Design

Two recorders feed the same server API ([api.md](api.md#capture-upload-desktop--extension)):
the **desktop app** (any application) and the **browser extension** (web apps, with richer
labels). Both produce the same step model from `opnrelay-core`.

## 1. Common behaviour

| Setting | Options | Default |
|---|---|---|
| Recording type | Steps · Video · Steps + video | Steps |
| Screenshot mode | Full screen · Active window · Region around click (size: S/M/L or custom px) | Region (M) |
| Multi-monitor | Monitor under cursor · All monitors (full-screen mode) | Monitor under cursor |
| Highlight | Draw click highlight on screenshot (stored as vector annotation, editable) | On |
| Auto-redaction | On / off | User preference |
| Typed text | Off · On (never for password fields) | Off |

The user picks these options per recording. Nothing is locked per department.

### Step generation
1. Input event detected (mouse down/up pair, double-click, right-click, key combo, focus+typing burst, URL change, app switch).
2. Debounce: typing bursts collapse into a single "Type in X" step; rapid duplicate clicks merge.
3. Screenshot taken **at mouse-down**, before the UI reacts, so the target is still visible.
4. Element info is resolved via accessibility APIs (desktop) or the DOM (extension).
5. A title is generated by `opnrelay-core::title` (localisable templates):
   `Click "{label}"`, `Double-click "{label}"`, `Type in "{field}"`, `Press Ctrl+S`,
   `Select "{option}" from "{field}"`, `Go to {host}{path}`, `Switch to {app}`.

### Redaction pipeline (client-side, before anything is persisted)
1. **Structural**: mask bounding boxes of password fields and elements marked sensitive (accessibility "protected" flag; DOM `type=password`, `autocomplete=cc-*`, `data-opnrelay-redact`, admin CSS selectors).
2. **Pattern**: OCR-free where possible. The extension reads DOM text nodes and their rects. The desktop app reads accessibility text values and their rects. Text matching patterns (email, phone, SSN, card numbers via Luhn check, DOB, MRN-like, custom regexes) is masked.
3. **Optional OCR** (desktop, off by default): a bundled lightweight OCR model (e.g. `ocrs`, pure Rust) catches text that is not exposed via accessibility (e.g. images, Citrix/RDP windows).
4. Redaction style is a solid box or a strong pixelation. Blur is avoided for automatic redaction because it can sometimes be reversed.
5. The user can review and toggle auto-redactions in the editor before publishing. **Un-redacting is impossible** unless the policy keeps originals.

### Privacy controls
- A persistent recording indicator (tray icon + small floating control).
- Global hotkeys: start/stop, pause/resume, and a "discard last step" key.
- Exclusion list (apps by bundle ID/exe name, sites by host); captures are suppressed while they are focused. The default list includes common password managers.
- Nothing is uploaded until the user stops and confirms.

## 2. Desktop recorder (`apps/desktop`)

A small native window (Rust + egui, see [ADR 0001](adr/0001-tauri-desktop.md)) plus a
command line (`opnrelay-recorder login|record`) for scripting and IT testing.

### How it works (v1)
| Concern | Implementation |
|---|---|
| Clicks, double-clicks, right-clicks, shortcuts | Polling the mouse/keyboard state every 8 ms (`device_query`). No global hooks and **no keystroke logging**: typing becomes one "Type in …" step when the user pauses, clicks, or presses Enter/Tab. |
| Screenshots | `xcap`: the monitor under the pointer, cropped to the area around the click (1000×640 points, HiDPI-aware), the active window, or the full screen. |
| Step titles | Desktop apps don't expose element names without accessibility APIs, so titles use the window: *Click in "Payroll – Employee record"*. The highlight box is drawn around the click point. |
| Privacy | The recorder's own window and common password managers are never recorded. Pause, undo last step, discard. |
| Sign-in | System browser + OAuth/PKCE loopback redirect; refresh token in the OS keychain (Windows Credential Manager, macOS Keychain, Secret Service), with a user-only file as fallback. |
| Upload | On finish: creates a draft guide, uploads screenshots, opens the editor in the browser. Failed uploads keep the steps for retry. |

### Platform notes
- **Windows 10/11:** works without extra permissions.
- **macOS:** the user must allow **Screen Recording** and **Accessibility** for OpnRelay
  Recorder in System Settings → Privacy & Security (first run).
- **Linux:** X11 sessions are supported. Wayland does not allow apps to observe global
  input or take screenshots freely, so record under an X11 session or use the browser
  extension for web apps.

### Planned
- Element labels via UI Automation (Windows), AXUIElement (macOS), AT-SPI (Linux).
- Global hotkeys for pause/stop, tray icon, encrypted local drafts.
- Optional on-device OCR to redact text in desktop screenshots (today: manual redaction in
  the editor).
- Video recording (M7). Installers: MSI, DMG, AppImage/deb/rpm with free signing (ADR 0007).

## 3. Browser extension (`apps/extension`)

### Targets
- Chrome, Edge (Chromium MV3) and Firefox (MV3). One TypeScript codebase built with
  esbuild into `dist/chromium` and `dist/firefox` (~21 KB).
- Distributed through the Chrome Web Store / Edge Add-ons / Firefox AMO **or** as
  self-hosted packages force-installed by policy.

### Permissions
- Required: `activeTab`, `scripting`, `storage`, `identity`.
- Optional, requested with a clear prompt: access to the OpnRelay server (when it is
  configured) and to web pages (when the first recording starts). Page access is what lets
  a recording continue across pages and sites.
- Content scripts are injected **only into the tab being recorded**, only while recording.

### Sign-in
`identity.launchWebAuthFlow` opens the server's `#/connect` consent page (OAuth 2.0
authorisation code + PKCE; see [api.md](api.md#1-authentication)). The refresh token is
kept in extension storage; the short-lived access token only in session storage.

### Enterprise install
- **Chrome / Edge:** force-install with the `ExtensionInstallForcelist` policy and set the
  server with managed storage (schema in `apps/extension/static/managed-schema.json`).
- **Firefox:** `policies.json` → `ExtensionSettings` (force install) and `3rdparty` →
  `Extensions` → `recorder@opnrelay.dev` → `serverUrl`.

### Recording
- Content script listens (capture phase, trusted events only) to `pointerdown` (click / right-click), `change` (typing into a field, choosing from a list) and `keydown` for shortcuts (Ctrl/⌘/Alt + key). After each navigation in the recorded tab the script is injected again.
- Screenshots are throttled to the browser limit (~2 per second) and queued, so very fast sequences of actions can show the page a moment after the action.
- Label resolution order: `aria-label` → `aria-labelledby` → `<label for>` → button/link text → `title` → `placeholder` → `name` → role + nearest heading.
- Before the screenshot: the content script draws redaction overlays on sensitive elements (DOM-level masking), then asks the service worker to `captureVisibleTab`, then removes the overlays. Unredacted pixels are never captured.
- "Area around each click" crops a 1000×640 CSS-pixel region around the click; "whole page view" keeps the visible tab. Coordinates are scaled to the real screenshot size.
- *Planned (M7):* video in the extension via `chrome.tabCapture` / `getDisplayMedia` with MediaRecorder (WebM). Firefox uses `getDisplayMedia` with a user prompt.
- Cross-origin iframes: the click and screenshot are captured, but labels inside the frame are not available yet (opt-in frame injection is planned).

## 4. Video & GIF

- Desktop video: H.264 MP4 via the OS encoder; step markers (timestamps) are recorded alongside, so "Steps + video" lets viewers jump to each step.
- Server worker (bundled `ffmpeg`, LGPL build): transcodes to web-friendly MP4/WebM, generates poster frames and **GIFs** (palette-optimised, max width/fps configurable). Redaction on video: auto-redaction applies to step screenshots. Continuous video is **not** auto-redacted in v1, because reliable per-frame redaction of arbitrary video is not achievable yet. The recorder shows a one-line note when video is selected, and users can trim the video or apply manual blur boxes over time ranges in the editor.
- Steps-to-GIF: animated GIF built from step screenshots with highlights (pure Rust `gif` crate), no ffmpeg needed.
