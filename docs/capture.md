# Capture Design

Two recorders feed the same server API ([api.md](api.md#capture-upload-desktop--extension)):
the **desktop app** (any application) and the **browser extension** (web apps, with richer
labels). Both produce the same step model from `opnrelay-core`.

## 1. Common behaviour

| Setting | Options | Default |
|---|---|---|
| Recording type | Steps · Video · Steps + video | Steps |
| Screenshot mode | Full screen · Active window · Region around click (size: S/M/L or custom px) | Region (M) |
| Multi-monitor | Monitor under cursor · All monitors (full-screen mode) | Monitor under cursor |
| Highlight | Draw click highlight on screenshot (stored as vector annotation, editable) | On |
| Auto-redaction | On / off | User preference |
| Typed text | Off · On (never for password fields) | Off |

The user picks these options per recording. Nothing is locked per department.

### Step generation
1. Input event detected (mouse down/up pair, double-click, right-click, key combo, focus+typing burst, URL change, app switch).
2. Debounce: typing bursts collapse into a single "Type in X" step; rapid duplicate clicks merge.
3. Screenshot taken **at mouse-down**, before the UI reacts, so the target is still visible.
4. Element info is resolved via accessibility APIs (desktop) or the DOM (extension).
5. A title is generated by `opnrelay-core::title` (localisable templates):
   `Click "{label}"`, `Double-click "{label}"`, `Type in "{field}"`, `Press Ctrl+S`,
   `Select "{option}" from "{field}"`, `Go to {host}{path}`, `Switch to {app}`.

### Redaction pipeline (client-side, before anything is persisted)
1. **Structural**: mask bounding boxes of password fields and elements marked sensitive (accessibility "protected" flag; DOM `type=password`, `autocomplete=cc-*`, `data-opnrelay-redact`, admin CSS selectors).
2. **Pattern**: OCR-free where possible. The extension reads DOM text nodes and their rects. The desktop app reads accessibility text values and their rects. Text matching patterns (email, phone, SSN, card numbers via Luhn check, DOB, MRN-like, custom regexes) is masked.
3. **Optional OCR** (desktop, off by default): a bundled lightweight OCR model (e.g. `ocrs`, pure Rust) catches text that is not exposed via accessibility (e.g. images, Citrix/RDP windows).
4. Redaction style is a solid box or a strong pixelation. Blur is avoided for automatic redaction because it can sometimes be reversed.
5. The user can review and toggle auto-redactions in the editor before publishing. **Un-redacting is impossible** unless the policy keeps originals.

### Privacy controls
- A persistent recording indicator (tray icon + small floating control).
- Global hotkeys: start/stop, pause/resume, and a "discard last step" key.
- Exclusion list (apps by bundle ID/exe name, sites by host); captures are suppressed while they are focused. The default list includes common password managers.
- Nothing is uploaded until the user stops and confirms.

## 2. Desktop app (Tauri 2)

### Platform matrix

| Capability | Windows 10/11 | macOS 13+ | Linux X11 | Linux Wayland |
|---|---|---|---|---|
| Global mouse/key events | `SetWindowsHookEx` (LL hooks) | `CGEventTap` (needs Accessibility permission) | XInput2 / XRecord | **Not available** to apps by design (see below) |
| Screenshots | Windows Graphics Capture / DXGI | ScreenCaptureKit (needs Screen Recording permission) | XShm / XGetImage | xdg-desktop-portal Screenshot / ScreenCast + PipeWire |
| Element labels | UI Automation | AXUIElement | AT-SPI2 | AT-SPI2 |
| Video encode | Media Foundation (H.264, HW accel) | AVFoundation / VideoToolbox | GStreamer (x264/VA-API) | GStreamer via PipeWire |

**Wayland limitation:** Wayland does not allow global input monitoring. Options are:
(a) ScreenCast portal video plus **manual step marking** via a hotkey registered through the
GlobalShortcuts portal (where the compositor supports it); (b) AT-SPI focus/activation
events as a best-effort click signal (works in GTK/Qt apps); (c) run the app under
XWayland. This must be documented clearly to Linux users.

### Implementation notes
- `opnrelay-capture` exposes a trait-based API: `InputSource`, `FrameSource`, `ElementInspector`, `VideoEncoder`, with one implementation per OS behind `cfg(target_os)`. Candidate crates: `windows` (official bindings), `objc2` / `screencapturekit`, `x11rb`, `ashpd` (portals), `atspi`, `gstreamer`.
- FFI is kept in small `unsafe`-allowed modules with safety comments; everything else is `forbid(unsafe_code)`.
- Screenshots are kept as PNG (lossless UI text) in memory, then WebP lossless or PNG on upload; the server re-encodes.
- HiDPI: frames are captured at native resolution and coordinates stored in physical pixels + scale factor.
- **Local draft store:** SQLCipher database in the app data dir; the key is in the OS keychain (`keyring` crate: Windows Credential Manager, macOS Keychain, Secret Service on Linux).
- **Offline:** drafts persist; the upload queue retries with backoff; uploads are resumable.
- **Distribution:** MSI/NSIS (Windows), DMG (macOS, universal binary), AppImage + .deb + .rpm (Linux; Flatpak later). No paid code-signing certificates; see [ADR 0007](adr/0007-no-paid-code-signing.md) and [deployment.md §8](deployment.md#8-client-rollout). Enterprise deployment: MSI supports silent install with a preconfigured server URL (`OPNRELAY_SERVER_URL` property / config file); macOS supports a `.mobileconfig`-delivered setting.

### Permissions onboarding
- macOS: guided prompts for **Accessibility** and **Screen Recording**, with deep links into System Settings.
- Windows: none required (no admin rights for install in per-user mode).
- Linux: portal consent dialogs; documentation for distros.

## 3. Browser extension

### Targets
- Chrome, Edge (Chromium MV3) and Firefox (MV3, Gecko-specific manifest keys). One TypeScript codebase built with Vite into `dist/chromium` and `dist/firefox`.
- Distributed through the Chrome Web Store / Edge Add-ons / Firefox AMO **and** as self-hostable packages for enterprise force-install via policy (`ExtensionInstallForcelist`, Firefox `policies.json`), preconfigured with the server URL through managed storage (`storage.managed`).

### Permissions
- `activeTab`, `scripting`, `storage`, `identity` (for sign-in), and host permission for the configured OpnRelay server only.
- Content scripts are injected **only into the tab where recording was started** (plus same-tab navigations while recording). There are no persistent `<all_urls>` content scripts.

### Recording
- Content script listens to `pointerdown`, `click`, `change`, `input` (debounced), `submit`, `keydown` (shortcuts only), and SPA navigations (History API patches + `popstate`).
- Label resolution order: `aria-label` → `aria-labelledby` → `<label for>` → button/link text → `title` → `placeholder` → `name` → role + nearest heading.
- Before the screenshot: the content script draws redaction overlays on sensitive elements (DOM-level masking), then asks the service worker to `captureVisibleTab`, then removes the overlays. Unredacted pixels are never captured.
- Region/element mode crops around the target element's bounding rect (`devicePixelRatio` aware).
- Video in the extension uses `chrome.tabCapture` / `getDisplayMedia` with MediaRecorder (WebM). Firefox uses `getDisplayMedia` with a user prompt.
- Cross-origin iframes: labels are unavailable without `all_frames` injection. Phase 1 captures the click and screenshot with a generic label; phase 2 adds opt-in frame injection.

## 4. Video & GIF

- Desktop video: H.264 MP4 via the OS encoder; step markers (timestamps) are recorded alongside, so "Steps + video" lets viewers jump to each step.
- Server worker (bundled `ffmpeg`, LGPL build): transcodes to web-friendly MP4/WebM, generates poster frames and **GIFs** (palette-optimised, max width/fps configurable). Redaction on video: auto-redaction applies to step screenshots. Continuous video is **not** auto-redacted in v1, because reliable per-frame redaction of arbitrary video is not achievable yet. The recorder shows a one-line note when video is selected, and users can trim the video or apply manual blur boxes over time ranges in the editor.
- Steps-to-GIF: animated GIF built from step screenshots with highlights (pure Rust `gif` crate), no ffmpeg needed.
